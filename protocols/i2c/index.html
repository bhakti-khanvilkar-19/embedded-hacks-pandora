I2C — Inter-Integrated Circuit

A two-wire, multi-drop, addressed bus. Where SPI trades pins for speed, I2C trades speed for pin count — many devices can share the same two wires because addressing happens in-band.

Wires and pull-ups

SDA
Serial data — bidirectional, shared by every device on the bus.
SCL
Serial clock — driven by the current bus master; can also be held low by a slave (clock stretching).

Both lines are open-drain: every device can only pull them low, never drive them high. A device idles by releasing the line, and external pull-up resistors (typically 2.2 kΩ–10 kΩ, board-dependent) bring it back to the logic-high rail. Missing or too-weak pull-ups is the most common reason a "correctly wired" I2C bus doesn't work at all.

Anatomy of a transaction

  1. START — master pulls SDA low while SCL is high.
  2. Address byte — 7 (or 10) address bits + 1 read/write bit, MSB first.
  3. ACK/NACK — receiver pulls SDA low for one clock to acknowledge each byte.
  4. Data byte(s) — 8 bits each, ACKed individually.
  5. STOP — master releases SDA while SCL is high.

A repeated START (a new START without an intervening STOP) is how a master switches from writing a register address to reading its value without releasing the bus — critical for the common "write register pointer, then read" pattern used by most I2C sensors.

Addressing

Most parts use 7-bit addresses (0x08–0x77 usable; some ranges reserved). Datasheets sometimes list an 8-bit "write address" that already includes the R/W bit shifted in — a frequent source of off-by-one-bit confusion when porting code between platforms.

Clock stretching and arbitration

Because SCL is open-drain, a slow slave can hold it low to pause the master mid-byte (clock stretching) — useful for peripherals that need time to prepare data, but it means SCL should always be read back, not assumed. In multi-master systems, arbitration works because a master monitors SDA while transmitting and backs off if it sees a bit it didn't drive — no separate bus-grant mechanism is needed.

Gotchas

Field notes
  • No pull-ups (or pull-ups on only one side of a level shifter) → bus stuck low, nothing acks.
  • A device that locks up mid-transaction can hold SDA low forever; toggling SCL manually up to 9 times is the standard "unstick the bus" recovery.
  • 7-bit vs. 8-bit address confusion — check whether the datasheet's listed address already includes the R/W bit.
  • On Linux, i2c-dev plus i2c-tools (i2cdetect, i2cget, i2cset) let you probe a bus from userspace — see Linux → Drivers.
