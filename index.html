Which language domain should I read?

Four domains in this notebook are specifically about programming languages, and they're meant to be read as one connected arc, not four unrelated stops. C is the shared foundation everything else builds on or contrasts against — Embedded C specializes it for bare metal, C++ extends it with object-oriented and generic-programming features, and Go is a genuinely different language kept as a sibling domain, explained throughout by direct contrast with what the other three already taught.

  • New to programming, or shaky on C fundamentals? — start with C. It assumes nothing and explains everything from a first program onward.
  • Writing firmware for a real microcontroller? — read C, then Embedded C specifically — the bare-metal-only behaviors (integer overflow, volatile, linker sections) that general C teaching skips.
  • Want object-oriented or generic programming on top of C? — C++, after C. Its own closing chapter comes back to what a bare-metal C++ codebase typically avoids from the full language.
  • Curious about a modern, concurrency-first alternative? — Go — every chapter is written assuming you already know C (and ideally C++), contrasting Go's choices against theirs directly.

How this notebook works

Every piece of knowledge is classified before it's written down: domain → category → topic. SPI and I2C are separate topics under Protocols; TCP, IP, and UDP are separated under Networking; C, Embedded C, C++, and Go are four separate domains rather than one giant "programming" catch-all, precisely so each can be read start to finish on its own terms. Linux, bootloaders, and Snap each evolve independently too. Nothing gets dumped into a catch-all folder. See GUIDE.md for the full convention on where new material belongs and how to add it.
