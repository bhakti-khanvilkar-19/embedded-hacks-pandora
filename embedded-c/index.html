Domain

Embedded C

Not a "learn C" tutorial — this domain is the specific discipline of reasoning about C the way it actually behaves on a microcontroller with a few kilobytes of RAM, no operating system to catch a mistake, and a CPU that will happily execute undefined behavior instead of complaining about it. Every topic here exists because it's a place embedded C diverges from "C as taught in a general programming course" in a way that produces real, field-reported bugs.

Why this domain is separate from Embedded

Embedded is the microcontroller itself — cores, pins, interrupts, timers. This domain is the language running on top of it: storage classes, integer representation, the compile/link pipeline, memory management, and the data structures a program is built out of. The distinction matters because everything here applies whether the target is an 8-bit AVR, a 32-bit Cortex-M, or a full Linux SBC — it's C discipline, not hardware.
